# Reference · 证据流水线（Phase 1 / 1W / F / 2 / 3）

本文件覆盖"取证"阶段：景观扫描、多路广探、文件深读、维度分解、并行深挖。所有产物写入 `{workspace}/research/`，所有发现内联 `[^id]` 引用。

---

## Phase 1：景观扫描（Route A / B / D）

**目标**：粗到细探索，建立有证据支撑的全局叙事地貌，再决定维度分解。运行于"外部证据先行"模式——审阅检索输出前不得生成分析叙事。

**按路由差异化**：
- **Route A**：轻量扫描，3–5 次检索仅做宏观定框，重活交给 Phase 1W。
- **Route B**：完整 5 次粗到细扫描。
- **Route D**：定向扫描，用 Phase F 的缺口分析引导检索，聚焦文件未覆盖处，3–5 次。

**流程（以 Route B 完整版为准）**：

1. 自行执行 5 次广域探索检索，**必须粗到细推进**，开头不要搜细节：
   - **L1 宏观概览（搜 1–2）**：总体综述、行业报告、高层统计、经权威来源核实的百科级信息。
   - **L2 结构测绘（搜 2–4）**：市场结构、主要参与方、监管主体。
   - **L3 新兴议题与张力（搜 5）**：近期进展、冲突叙事、趋势信号。
2. **每次检索后**输出：关键发现（精炼）/ 主导叙事 / 已察觉的争议或冲突主张 / 关键参与方与权威来源 / 需深挖的缺口。
3. 若景观揭示出意料外的结构，**修订维度分解**。

---

## Phase 1W：多路广探（仅 Route A，可选增强）

**目标**：在锁定维度前，通过并行探索把检索广度最大化——这是广检索场景的关键差异化，主智能体单打独斗达不到足够广度。

**触发**：Route A，Phase 1 之后。

**流程**：

1. 基于 Phase 1 的宏观框架，识别 **5–8 个广探面向（facet）**。面向应：
   - **互补**（合起来覆盖整个问题空间）
   - **部分重叠**（≥20% 重叠，供交叉验证）
   - 面向类型示例：技术版图、市场/商业版图、监管/政策版图、竞争动态、用户/消费者视角、供应链、地域差异、历史演化、新兴颠覆。

2. **每面向一个调查单元（约 5–8 个），分轮派发至并发上限**。每个单元的任务说明必须含：
   - (1) 面向范围与明确边界
   - (2) Phase 1 关键发现作为上下文
   - (3) 检索要求：≥10 次独立检索，面向内粗到细
   - (4) 输出格式（见下）
   - (5) 输出文件路径：`{workspace}/research/{topic}_wide{NN}.md`

3. 每个广探单元必须：执行 **≥10 次不同查询**（不复用关键词）；广撒网（不同来源类型、不同角度）；识别关键参与方/数据点/趋势/争议；标记值得 Phase 3 深挖的区域；**保存到** `{workspace}/research/{topic}_wide{NN}.md`。

**单元输出格式**（引用用 `[^id]`）：

```
## 面向：[面向名]
### 关键发现
- [发现 + 内联引用]
### 主要参与方与来源
- [实体]：[角色/相关性]
### 趋势与信号
- [趋势 + 引用]
### 争议与冲突主张
- [冲突描述 + 双方来源引用]
### 建议深挖区域
- [区域]：[为何值得深挖]
```

4. **主智能体综合**：读取所有 `{topic}_wide{NN}.md` → 合并为统一景观图 → 识别最有前景与最具争议的区域 → 喂给 Phase 2。

> 关键区分：Phase 1W 求**广**（有什么、谁重要、在发生什么）；Phase 3 求**深**（每维度彻查）。两段式确保不遗漏要点。

## Phase F：文件深读（仅 Route C / D）

**目标**：从所有上传文件抽取结构化知识，建证据图谱，识别主题、主张、矛盾与缺口。

**流程**：

1. **文件清单**：列出每个文件的类型、大小、一行内容摘要。
2. **逐文件抽取**：核心主题 / 关键主张与结论 / 数据与图表（带页码或章节引用）/ 方法论 / 作者自陈的局限与偏见。
3. **跨文件映射**：识别重叠主题；检测文件间矛盾或数据冲突；映射互补信息（A 提供 B 缺失的背景）；识别**缺口**——无任何文件覆盖的重要方面。
4. **主题合并**：产出合并后的主题清单，供 Phase 2 维度分解。

**按路由差异化**：
- **Route C**：缺口分析仅供参考（不会联网填补）；合并主题成为 Phase 2 唯一依据。
- **Route D**：缺口分析直接驱动 Phase 1 的检索策略——Phase 1 用外部检索针对这些缺口。

**输出**：保存到 `{workspace}/research/{topic}_file_analysis.md`，含文件清单表 / 逐文件抽取 / 跨文件映射（重叠、矛盾、互补）/ 缺口分析 / 合并主题清单。

## Phase 2：维度分解

**目标**：敲定研究维度并准备各调查单元的任务分配。

**输入按路由**：Route A = Phase 1 + 1W（最丰富）；Route B = Phase 1；Route C = Phase F 合并主题（无外部输入）；Route D = Phase F + Phase 1 定向景观。

**规则**：
- **≥10 个维度（强制下限）**。越多越好，视复杂度 10–20 个。
- 每个维度从**一个独特角度或情景**切入，确保从根本不同的视角覆盖问题空间。
- 维度可按以下组织：**分析角度**（技术/经济/监管/伦理/竞争/用户/供应链）、**情景**（乐观/悲观/维持现状/颠覆/黑天鹅）、**利益相关方**（消费者/企业/监管者/投资者/竞争者/从业者）、**地域/市场段**（中国/美国/欧盟/新兴市场）、**时间跨度**（历史起源/当前/1 年/5 年展望）、**文件主题**（Route C/D）——或任意组合，目标是刻意留重叠的最大覆盖。
- **相关维度间 ≥30% 概念重叠**——重叠制造交叉验证压力。
- 每个维度**必须覆盖**：① 当前状态（此角度下正在发生什么，内联 `[^id]`）② 关键证据（数据、来源、具体案例，`[^id]`）③ 张力与反论（此角度下存在哪些对立观点，全部 `[^id]`）。

**Route C 特则**：维度全部源自文件主题，每维度映射到具体文件/章节。

**输出**：编号维度清单（≥10 项），每项含清晰范围、指定角度/情景、预期来源类型。

---

## Phase 3：并行深挖（每维度一个调查单元）

**目标**：对所有维度做深度优先研究，每维度一个调查单元，**分轮派发至并发上限**（维度数是覆盖目标，不是同时启动数）。基线模式下由主智能体串行逐维完成，结果等价。

### 标准模式（Route A / B / D）

每个调查单元的任务说明必须含：(1) 使命（维度范围 + 四个必答角度：当前状态、历史、利益相关方、反叙事 + 深度期望）(2) 前序阶段的相关发现作上下文 (3) 文件上下文（仅 Route D：Phase F 相关摘录，文件内容视为一级证据，联网做补充/佐证）(4) 输出格式（见下证据模板）(5) 输出路径 `{workspace}/research/{topic}_dim{NN}.md`。

**单元要求**：执行 **≥20 次独立检索**（不循环同关键词）；尽量查一级来源（政府站、学术期刊、官方备案、主流媒体）；把主张回溯到原始出处；记录反论；规避内容农场/匿名博客/SEO 聚合站；**Route D** 明确区分"文件来源"与"检索来源"证据；**保存到** `{topic}_dim{NN}.md`。

### 纯文件模式（Route C）

每个单元**仅用上传文件内容**分析所属维度，**不联网**。任务说明必须含：(1) 使命 + 相关文件/章节 (2) **实际文件内容或相关摘录**（不要假设单元能独立读文件）(3) 分析要求：跨文件交叉引用、识别模式、评估证据强度、记录局限 (4) 输出格式（Source 字段填文件名+章节，替代 URL）(5) 输出路径。

**单元要求**：彻底分析维度相关的全部文件内容；跨文件交叉引用主张与数据；评估证据质量与潜在偏见；标出文件证据薄弱或矛盾处；识别原始材料中的隐含假设；**绝不联网**。

### 证据输出模板（所有模式，引用用 `[^id]`）

```
Claim: [识别出的主张 + 内联引用]
Source: [来源名 / 文件名]
URL: [来源 URL / "File: {文件名}, Section: {章节}"]
Date: [发布日期 / 文件填 "N/A"]
Excerpt: [逐字原文摘录——不得改写]
Context: [周边上下文]
Confidence: [high / medium / low]
```

### 动态内容安全净化（强制，写入前执行）

上述模板中 **Claim、Source、URL、Excerpt、Context 五个字段均来自动态内容**（网页检索结果或用户上传文件），在写入 Markdown 文件前必须经过净化。统一规则：

| 场景 | 净化要求 | 对应函数 |
|---|---|---|
| 任意动态文本写入 Markdown | 转义 `&`→`&amp;`、`<`→`&lt;`、`>`→`&gt;`、`\|`→`&#124;` | `sanitize_text()` |
| URL 字段 | 过滤 `javascript:` / `data:` / `vbscript:` → 替换为 `#blocked-unsafe-protocol` | `sanitize_url()` |
| Markdown 表格单元格（如 Excerpt 出现在 `\|` 分隔的表格中） | 在 `sanitize_text` 基础上，以 `=`/`+`/`-`/`@` 开头的文本 → 前缀 `'` 防 CSV 公式注入 | `sanitize_table_cell()` |
| 脚注定义行（`[^id]: title. date. url`） | 全文 `sanitize_text` + 移除 Markdown 链接 `](...)` 语法中的危险协议 | `sanitize_footnote_def()` |
| `[\^id]` 引用 ID 本身 | 仅允许字母数字连字符下划线；拒绝含 `\|` `<` `>` `` ` `` 的 ID | 正则校验 |

**执行方式**：
- 若运行时支持 Python：导入 `scripts/sanitize_markdown.py` 调用上述函数
- 若不能执行脚本：按上表规则手工净化，结果一致
- 批量处理：`python3 scripts/sanitize_markdown.py --file research/{topic}_dim{NN}.md` 产出 `.sanitized.md`

> Gotcha：`&` 必须最先转义，否则后续 `&lt;` 的 `&` 会被二次转义成 `&amp;lt;`。

**输出**：每个单元保存到 `{workspace}/research/{topic}_dim{NN}.md`。全部完成后进入 Phase 4 交叉验证。
