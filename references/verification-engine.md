# Reference · 交叉验证引擎（Phase 4 / 5）★ 本 skill 的签名能力

这是"可信度分级"的核心。主智能体在此把散落于各维度的发现，按证据强度归入四级，显式暴露并分析矛盾，产出可供报告直接引用的**可信度契约文件**。

---

## Phase 4：交叉验证引擎

**目标**：比对所有维度输出，分类可信度，浮现矛盾，并**把结果落文件**供下游报告使用。

**流程**：

1. 读取所有 `{workspace}/research/{topic}_dim{NN}.md`（Route A 还包括 `{topic}_wide{NN}.md`；Route C/D 还包括 `{topic}_file_analysis.md`）。
2. 把每条发现归入四级之一：

| 级别 | 判定标准 |
|---|---|
| **Consensus Zone（共识区）** ★ | **所有**维度一致确认的发现，无任何单元提出质疑或不同数据——天然最高可信信号 [^storm] |
| **High Confidence（高）** | ≥2 个调查单元、从**独立来源**确认，证据一致 |
| **Medium Confidence（中）** | 1 个单元从**权威来源**确认 |
| **Low Confidence（低）** | 弱来源、博客级证据，或单一未经核实的主张 |
| **Conflict Zone（冲突区）** | 单元间存在统计分歧、解读分歧、时间不一致，或**同一指标数值打架**（两单元对同一统计给出不同数字） |
| **Blind Spot（盲区）** ★ | 重要方面但在所有调查单元中**均未被触及**——往往反映整个领域的研究空白或集体认知盲点，一旦点明极有价值 [^storm] |

3. **显式列出所有 Conflict Zone 条目**——矛盾要高亮并分析，**绝不压制**。
   - **时间冲突属冲突区**：若各单元报告的是**不同时期**的同一指标数据，标为时间不一致，并记录每个数据点所属时间。
4. **提取共识区**：扫描全部维度，找出**所有维度都一致确认**的发现——无反对、无不同数据、无质疑，归入 Consensus Zone。这是本次研究中最可被信任的结论。
5. **检测盲区**：主动问自己——"围绕本主题，有什么重要问题、关键角度或利益相关方，在全部维度输出中一次都没出现过？"将此类盲区显式记录。盲区比已有的任何发现都更能揭示认知边界。
6. 判断是否需要 Phase 5（存在任何冲突区，或关键低可信条目）。
   - **Route C 例外**：跳过 Phase 5（不许联网）。矛盾按原样记录，带入 Phase 6。
5. 全程保留内联 `[^id]`；冲突区分析必须 `[^id]` 引用所有涉事来源。

**冲突分类细则**（记录时标明类型，便于复核）：
- **数值冲突**：同一指标不同数字 → 记录各自数值、时间、出处、口径差异。
- **解读冲突**：同一事实不同结论 → 记录各方立场与论据。
- **时间冲突**：数据来自不同时期却被并列 → 标注时间线。
- **来源冲突**：一级来源与二手转述打架 → 以可回溯的一级来源为准，并记录分歧。

**输出**：把完整交叉验证结果（四级分类 + 冲突区分析）保存到 **`{workspace}/research/{topic}_cross_verification.md`**。此文件承载可信度分类，是报告写作的关键输入。

> 可选增强：运行 `scripts/tally_confidence.py {workspace}/research/` 自动统计各级数量、汇总冲突清单，减少手工计数错误。若无法执行脚本，按上表手动统计。

### Phase 4.5：认知自检（交付前系统性自查）[^storm]

**目标**：在进入洞察提炼前，对交叉验证结果做一次"同行评审式"的元检查——对标学术同行的审稿标准，发现偏见、标出最弱项、补问遗漏视角。这是交付可信度的最后一关。

**流程**：

1. **最不可靠主张**：在所有已归类发现（共识/高/中/低/冲突）中，**哪一条可信度最弱**？要验证它需要什么具体信息？
2. **视角偏斜检查**：审视全部维度——是否存在某一类立场或角度（如产业乐观叙事）在综合输出中的篇幅、权重**显著压倒**了对立角度（如监管/质疑/用户端）？若有，记录为"潜在偏斜"，在报告中主动提示读者。
3. **遗漏视角补问**：是否还存在**一个本应纳入但因维度设计而未覆盖的第 N+1 个视角**？如果该视角可能改变整体结论，记录为"未纳入视角"，建议后续补研。
4. **综合完整度等级**：对本次交叉验证结果的覆盖完整性、证据充分度、偏见控制给出一个 **A / B / C / D 等级**（A=各维度均衡、证据充分、盲区可控；B=基本完整但有轻度偏斜；C=有明显缺角；D=重大遗漏、不宜作为决策依据）。

**输出**：将以上四项自查结果作为 `### 认知自检` 章节追加到 `{workspace}/research/{topic}_cross_verification.md` 末尾。**不改变**已有的可信度分类，仅做元标注——让读者知道本报告的置信边界。

## Phase 5：定向复核（条件触发）

**目标**：化解冲突、加固弱发现。

**触发**：仅当 Phase 4 识别出冲突区或关键低可信条目时执行。**Route C 不可用**（纯文件研究不能联网）。

**流程**：

1. 对每个未决条目，派一个聚焦调查单元，带上：具体的冲突主张及其来源；找独立证据以化解分歧的指令；**每个冲突至少 3 次额外检索**。
2. 迭代直到每个条目要么：
   - **已化解**——凭新证据重分类为高/中可信；
   - **显式标记未决**——记录为该领域内真实存在的分歧。
3. **更新** `{workspace}/research/{topic}_cross_verification.md` 写入复核结果。

所有复核输出必须保留内联 `[^id]`。

## 为什么"分级 + 溯源 + 矛盾消解"是本 skill 的价值内核

- **抗幻觉**：每条结论必须挂来源、标可信度，模型无法用"看似合理"蒙混。
- **决策友好**：读者一眼看出哪些是共识（可拍板）、哪些需谨慎（低可信）、哪些还在打架（冲突区）、哪些被所有人遗漏了（盲区）。
- **忠于真实世界**：真实信息环境充满矛盾与盲区。显式暴露冲突与认知空白，比给出一个"干净但错误"的答案更有价值。

共识区与盲区概念参考了斯坦福 STORM 研究法 [^storm]；认知自检对标学术同行评审标准。

[^storm]: Yijia Shao et al. "STORM: Synthesis of Topic Outlines through Retrieval and Multi-perspective Question Asking." NAACL 2024. https://storm.genie.stanford.edu/
