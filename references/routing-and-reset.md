# Reference · 路由判定与 Epistemic Reset（Phase 0）

主智能体在任何检索/分析前，先完成路由判定与认知重置。本文件是 SKILL.md「Phase 0」的细则。

## Phase 0：意图与输入路由

**目标**：在动手研究前，把请求归入正确的路由。

**判定流程**：

1. **检查上传文件**
   - 有文件 + 明确"仅基于文件/不要联网/只看上传的" → **Route C（纯文件研究）**
   - 有文件 + "参考/结合/帮我补全/据此" 或未作限制 → **Route D（文件增强研究）**
   - 无文件 → 进入第 2 步

2. **评估主题宽度**
   - 宽泛、开放、景观级（"XX 行业现状""帮我研究 XX 领域""A vs B vs C 全面对比"）→ **Route A（广度检索）**
   - 具体、有界、可识别维度的问题 → **Route B（聚焦检索）**

3. **歧义时的默认**
   - 主题明显多面且无明确切入角 → 默认 **Route A**
   - 文件意图不清 → 优先 **Route D** 而非 C（输出更丰富，且不违背"参考文件"的隐含意图）

**输出**：用一句话说明所选路由及理由，然后进入该路由的首个阶段。

### 分类信号速查

| 信号 | 路由 |
|---|---|
| 文件 + "只基于文件" / "仅上传内容" / "不要搜索" | C |
| 文件 + "参考" / "结合" / "帮我补全" / 无限制 | D |
| 无文件 + 宽泛/探索性主题 | A |
| 无文件 + 具体/有界问题 | B |

### 各路由的阶段编排

- **Route A**：Phase 1（轻量景观）→ Phase 1W（多路广探）→ Phase 2 → Phase 3 → Phase 4 →（Phase 5）→ Phase 6 → Phase 7
- **Route B**：Phase 1（完整景观）→ Phase 2 → Phase 3 → Phase 4 →（Phase 5）→ Phase 6 → Phase 7
- **Route C**：Phase F（文件深读）→ Phase 2（从文件主题分解）→ Phase 3-F（仅文件深挖，**无联网**）→ Phase 4 → Phase 6 → Phase 7（**跳过 Phase 5**）
- **Route D**：Phase F → Phase 1（针对文件缺口的定向景观）→ Phase 2（文件主题 + 外部景观合并）→ Phase 3（每单元带文件上下文 + 联网补充）→ Phase 4 →（Phase 5）→ Phase 6 → Phase 7

## Epistemic Reset Rule（每次开工必做）

在任何分析或叙述生成之前，系统必须：

- **假设内部知识可能过期或不完整**。先用 Shell/工具获取**当前日期时间**，再做任何分析或检索。
- **时间敏感性作为硬约束**：当用户请求含时间要求（"2026 Q1""近 6 个月""最新""当前"），把指定或隐含的时间窗当作硬约束——检索必须瞄准该窗口，窗口外的发现要显式标注。
- **先检索、后结论**（Route C 除外）：先做外部广探建立证据地貌，不得在拿到检索/文件输出前生成任何事实性主张。
- **检索语言规则**：所有检索用语必须与用户提问语言一致。中文提问→中文检索；英文提问→英文检索。确保结果贴合用户所处语境。
- **溯源契约**：所有产物用标准 Markdown 脚注——正文 `[^id]` 标记 + 文末 `[^id]: 标题. 日期. URL` 定义。为同一 URL 复用同一稳定 `id`。完整规则见 `insight-and-output.md`。

## 搜索预算（按路由，跨全部轮次的总覆盖目标）

并发受限时按比例缩减，不要为凑数强行膨胀：

| 路由 | 预算 |
|---|---|
| Route A | 广探单元(约 5–8) × ≥10 次检索 + 深挖单元(每维度一个) × ≥20 次检索 |
| Route B | 深挖单元(每维度一个) × ≥20 次检索 |
| Route C | **0 次联网**（纯文件） |
| Route D | 深挖单元 × ≥15 次检索（文件已提供基础证据，故减量） |

## 来源质量分层（贯穿全程）

- **优先**：政府官网、学术期刊、官方备案/财报、权威主流媒体、标准组织。
- **谨慎**：行业自媒体、二手转述——需回溯到原始出处。
- **规避**：内容农场、匿名博客、SEO 聚合站。
- 文件类路由中，用户提供的文件视为**一级权威来源**。
